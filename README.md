## Пример Структуры проекта

```text
Template_CMake/
│
├── CMakeLists.txt
├── cmake/
│
├── include/
│   └── core/
│       └── math_utils.hpp
│
├── src/
│   ├── CMakeLists.txt
│   └── math_utils.cpp
│
├── app/
│   ├── CMakeLists.txt
│   └── main.cpp
│
├── tests/
│   ├── CMakeLists.txt
│   └── test_math.cpp
│
└── external/
```
**Основная идея:** в CMake можно создавать *target* практически для любой части проекта.  
**Target** — это именованная сущность, которая по сути является контейнером для всех свойств, связанных с модулем. Внутри такого контейнера могут храниться:
- исходные файлы,
- подключаемые библиотеки,
- директории заголовков,
- флаги компиляции,
- требования к стандарту языка,
- другие зависимости
- и другие параметры сборки

Иными словами, **target — это метка, описывающая модуль программы**. У этой метки есть имя, и именно это имя обычно указывается первым аргументом в основных командах CMake.

На практике таргеты чаще всего называют:
- по имени исполняемого файла — если таргет представляет приложение;
- по имени библиотеки — если таргет соответствует библиотеке или её части.

После объявления одного или нескольких таргетов их можно настраивать, связывать друг с другом зависимостями и выполнять другие операции, необходимые для организации сборки проекта.

## Общие слова
Я ниже приведу план-структуру и пояснения что и зачем делается, а также смотрите в самих CMakeLists.txt этого репозитория команды для этого примера.

## Главный CmakeLists.txt
Он создается в корне проекта. Я создаю в нем общие настройки проекта и подключаю отдельные модули в нем(директории, библиотеки, которые будут нужны для сборки всего).

Основные команды в нем:
```CMake
cmake_minimum_required(VERSION 3.20)
```
задает версию Cmake
```CMake
project(Template_CMake
    VERSION 1.0
    DESCRIPTION "Enterprise C++ Project with dependencies"
    LANGUAGES CXX
)
```
устанавливает имя метки целого проекта (**соответственно лучше называть таргет проекта по названию вашего репозитория**). Оно нужно, если будете подключать свой проект в другие, делиться им и по-хорошему для этого нужно будет прописать config, но об этом потом. Сейчас имя проекта для вашей сборки особо не нужно.
```CMake
set(CMAKE_CXX_STANDARD 20)
set(CMAKE_CXX_STANDARD_REQUIRED ON)
set(CMAKE_CXX_EXTENSIONS OFF)
```
команды, задающая настройки проекта.
```CMake
add_subdirectory(src)
add_subdirectory(app)
add_subdirectory(tests)
```
подключает модули(*напоминаю, что имя этих таргетов лучше называть по названию ваших директорий*), и при выполнении главного файла CMake будет заходить по этим меткам, для которых вы пропишите в других файлах директории и все остальное, и эти таргеты тоже будут исполнены.

Еще в этом файле я писал команду *find_package*, но я ниже о ней напишу.

Таким образом, главный  CMake файл у нас содержит общую информацию и легко редактируется, можем подключать просто таргеты, а всю реализацию в них оставляем на внутренние CMake файлы, к которым сейчас и перейдем. 

Смотрите подробнее в корневом файле.

## app
Так как мы хотим сделать исполняемый файл, то перейдем к файлу CMakeLists.txt в директории app.

```CMake
add_executable(app main.cpp)
```
эта команда делает таргет исполняемого файла *app*, который содержит файл *main.cpp*, а также будет создаваться и сам исполняемый файл с именем *app*.

Следующая команда прилинкует к нашему таргету *app* таргет *core*(тип библиотеки) c режимом наследования(назовем это так) PRIVATE(ниже поясню что это).

```CMake
target_link_libraries(app
    PRIVATE core
)
```
то есть все, чем будет наполнен таргет  *core* будет прилинковано в *app*. Таким образом *main.cpp* будет слинкован с файлами, которые у нас располагаются в библиотке *core* (точнее в таргете).

В директории *core*  у нас лежит хедер *math_utils.hpp* и **там нет CMake файлов**. Поэтому заглянем в *src*  где лежит *math_utils.cpp*.

## src

Первая команда

```CMake
add_library(core)
```
мы сделали таргет *core* типа библиотеки. Дальше "наполним" его (подключим к нему) файлом кода.

```CMake
target_sources(core
    PRIVATE
        math_utils.cpp
)
```
Следующим действием указываем где лежам хедеры, которые нужны только для сборки этого файла(дальше, все, чем мы наполним *core* будет доступно при обращении к нему)

```CMake
target_include_directories(core
    PUBLIC
        ${PROJECT_SOURCE_DIR}/include
)
```

а также можем прилинковать необходимые таргеты! к этому файлу

```CMake
target_link_libraries(core
    PUBLIC
        Eigen3::Eigen
        Threads::Threads
)
```

Eigen3::Eigen,  Threads::Threads - это тоже таргеты, здесь Eigen3 - это имя другого проекта(вот здесь нам и понадобились имена проектов), который уже собран и у которого есть свои файлы CMake и через имя проекта мы обращаемся к таргету Eigen. Вообще, такое обращение к таргетам через имя проекта используется, если мы использовали команду *find_package* она добавляла уже собранные проекты или хедер-онли. То есть Cmake не будет там генерировать правила для сборки. 

**Сейчас их нет в проекте, но как будто есть отдельные директории с собранными библиотеками.**

```CMake
target_compile_features(core
    PUBLIC cxx_std_20
)
```
 здесь просто указали какая версия языка будет использоваться при создании исполняемых команд.

## tests
Это будет отдельный исполняемый файл с тестами для нашего основного файла. 

```CMake
add_executable(test_math test_math.cpp)
```

Так как мы тестируем функцию *add* из файла *math_utils* то подключаем таргет *core* в котором содержится все упоминания(файлы, хедеры, настройки компиляции) для подключамем библиотеки *math_utils*

```CMake
target_link_libraries(test_math
    PRIVATE core
)
```
