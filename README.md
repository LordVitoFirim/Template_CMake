## Пример Структуры проекта

```text
Template_CMake/
│
├── CMakeLists.txt
├── cmake/
│
├── include/
│   └── core/
│       └── math_utils.hpp
│
├── src/
│   ├── CMakeLists.txt
│   └── math_utils.cpp
│
├── app/
│   ├── CMakeLists.txt
│   └── main.cpp
│
├── tests/
│   ├── CMakeLists.txt
│   └── test_math.cpp
│
└── external/
```
**Основная идея:** в CMake можно создавать *target* практически для любой части проекта.  
**Target** — это именованная сущность, которая по сути является контейнером для всех свойств, связанных с модулем. Внутри такого контейнера могут храниться:
- исходные файлы,
- подключаемые библиотеки,
- директории заголовков,
- флаги компиляции,
- требования к стандарту языка,
- другие зависимости
- и другие параметры сборки

Иными словами, **target — это метка, описывающая модуль программы**. У этой метки есть имя, и именно это имя обычно указывается первым аргументом в основных командах CMake.

На практике таргеты чаще всего называют:
- по имени исполняемого файла — если таргет представляет приложение;
- по имени библиотеки — если таргет соответствует библиотеке или её части.

После объявления одного или нескольких таргетов их можно настраивать, связывать друг с другом зависимостями и выполнять другие операции, необходимые для организации сборки проекта.

## Главный CmakeLists.txt
Он создается в корне проекта. Я создаю в нем общие настройки проекта и подключаю отдельные модули в нем(директории, библиотеки, которые будут нужны для сборки всего).

Основные команды в нем:
```
cmake_minimum_required(VERSION 3.20)
```
задает версию Cmake
```
project(Template_CMake
    VERSION 1.0
    DESCRIPTION "Enterprise C++ Project with dependencies"
    LANGUAGES CXX
)
```
устанавливает имя метки целого проекта (**соответственно лучше называть таргет проекта по названию вашего репозитория**). Оно нужно, если будете подключать свой проект в другие, делиться им и по-хорошему для этого нужно будет прописать config, но об этом потом. Сейчас имя проекта для вашей сборки особо не нужно.
```
set(CMAKE_CXX_STANDARD 20)
set(CMAKE_CXX_STANDARD_REQUIRED ON)
set(CMAKE_CXX_EXTENSIONS OFF)
```
команды, задающая настройки проекта.
```
add_subdirectory(src)
add_subdirectory(app)
add_subdirectory(tests)
```
подключает модули(*напоминаю, что имя этих таргетов лучше называть по названию ваших директорий*), и при выполнении главного файла CMake будет заходить по этим меткам, для которых вы пропишите в других файлах директории и все остальное, и эти таргеты тоже будут исполнены.

Таким образом, главный  CMake файл у нас содержит общую информацию и легко редактируется, можем подключать просто таргеты, а всю реализацию в них оставляем на внутренние CMake файлы, к которым сейчас и перейдем.
