# Базовая шпаргалка для CMake

Это учебный шаблон C++ проекта. Идея простая: показать, как разложить код по
папкам и собрать его через CMake так, чтобы проект не превращался в одну большую
кучу файлов.

CMake здесь нужен не для красоты. Он помогает описать проект один раз, а потом
собирать его нормальными командами.

## Зачем вообще нужен CMake

Если у нас один файл, можно собрать его руками:

```bash
c++ main.cpp -o app
```

Но в реальном проекте быстро появляются:

- несколько `.cpp` файлов;
- заголовочные файлы `.hpp`;
- папка с библиотекой;
- отдельная папка с приложением;
- тесты;
- флаги компилятора;
- зависимости.

И вручную команда становится длинной и неудобной. Нужно помнить, какие файлы
компилировать, где искать заголовки, какие библиотеки подключать.

CMake решает именно эту проблему. Он не компилятор. Он читает файлы
`CMakeLists.txt` и готовит проект к сборке.

Грубо говоря:

```text
мы пишем CMakeLists.txt
        │
        ▼
    CMake читает описание проекта
        │
        ▼
    CMake создает файлы сборки
        │
        ▼
    компилятор собирает программу
```

## Пример структуры проекта

```text
Template_CMake/
│
├── CMakeLists.txt
├── cmake/
│   └── CompilerWarnings.cmake
│
├── include/
│   └── core/
│       └── math_utils.hpp
│
├── src/
│   ├── CMakeLists.txt
│   └── math_utils.cpp
│
├── app/
│   ├── CMakeLists.txt
│   └── main.cpp
│
├── tests/
│   ├── CMakeLists.txt
│   └── test_math.cpp
│
├── external/
│
└── README.md
```

## Что лежит в каждой папке

`include/` — публичные заголовочные файлы.

Тут лежит то, что другие части проекта могут подключать через `#include`.
Например:

```cpp
#include "core/math_utils.hpp"
```

`src/` — реализация библиотеки.

Тут лежат `.cpp` файлы, где написано, как именно работают функции.

`app/` — основная программа.

Тут лежит `main.cpp`. Это точка входа, то есть место, откуда программа стартует.

`tests/` — простые проверки.

Тут лежит маленькая программа, которая вызывает функцию из библиотеки и проверяет,
что результат правильный.

`cmake/` — дополнительные CMake-файлы.

Сюда удобно выносить настройки, чтобы главный `CMakeLists.txt` не становился слишком
длинным.

`external/` — место под сторонние библиотеки.

Сейчас проект не использует внешние зависимости, но папка оставлена на будущее.

## Главная идея структуры

В этом проекте код разделен на три части:

```text
library: core
    ↑
    │
используют
    │
    ├── app
    └── test_math
```

То есть логика лежит в библиотеке `core`, а приложение и тестовая программа просто
подключают эту библиотеку.

Это удобно, потому что код можно проверять отдельно от основного `main.cpp`.

## Главный `CMakeLists.txt`

Корневой `CMakeLists.txt` начинается так:

```cmake
cmake_minimum_required(VERSION 3.20)
```

Эта строка говорит: для проекта нужен CMake версии 3.20 или новее.

Дальше описывается проект:

```cmake
project(Template_CMake
    VERSION 1.0
    DESCRIPTION "Basic C++ project template with CMake"
    LANGUAGES CXX
)
```

Здесь:

- `Template_CMake` — имя проекта;
- `VERSION 1.0` — версия;
- `DESCRIPTION` — описание;
- `LANGUAGES CXX` — говорим, что проект на C++.

Потом задается стандарт C++:

```cmake
set(CMAKE_CXX_STANDARD 20)
set(CMAKE_CXX_STANDARD_REQUIRED ON)
set(CMAKE_CXX_EXTENSIONS OFF)
```

На пальцах:

- первая строка выбирает C++20;
- вторая строка говорит, что этот стандарт обязателен;
- третья отключает нестандартные расширения компилятора.

## Подключение подпапок

В корневом файле есть такие строки:

```cmake
add_subdirectory(src)
add_subdirectory(app)

enable_testing()
add_subdirectory(tests)
```

`add_subdirectory(src)` говорит CMake: зайди в папку `src/` и прочитай ее
`CMakeLists.txt`.

`add_subdirectory(app)` делает то же самое для приложения.

`enable_testing()` включает поддержку тестов.

`add_subdirectory(tests)` подключает папку с тестовой программой.

То есть главный файл не обязан знать все детали. Он просто говорит:

```text
собери библиотеку
собери приложение
включи тесты
собери тесты
```

## Библиотека `core`

В `src/CMakeLists.txt` создается библиотека:

```cmake
add_library(core)
```

Потом к ней добавляется `.cpp` файл:

```cmake
target_sources(core
    PRIVATE
        math_utils.cpp
)
```

`PRIVATE` здесь значит: этот файл нужен только для сборки самой библиотеки.

Дальше CMake узнает, где искать заголовочные файлы:

```cmake
target_include_directories(core
    PUBLIC
        ${PROJECT_SOURCE_DIR}/include
)
```

`PUBLIC` значит: эта папка нужна не только самой библиотеке, но и тем, кто будет
подключать библиотеку `core`.

Например, `app` подключает `core`, значит `app` тоже сможет найти:

```cpp
#include "core/math_utils.hpp"
```

## Заголовок и реализация

В заголовке `include/core/math_utils.hpp` лежит объявление:

```cpp
#pragma once

namespace core
{
    int add(int a, int b);
}
```

Это как объявление: такая функция существует.

В `src/math_utils.cpp` лежит реализация:

```cpp
#include "core/math_utils.hpp"

namespace core
{
    int add(int a, int b)
    {
        return a + b;
    }
}
```

Это уже ответ на вопрос: что функция делает.

## Приложение

В `app/CMakeLists.txt` создается исполняемый файл:

```cmake
add_executable(app main.cpp)
```

Потом приложение подключается к библиотеке:

```cmake
target_link_libraries(app
    PRIVATE core
)
```

На пальцах: перед тем как собрать `app`, CMake должен собрать `core`, потому что
приложение использует функции из этой библиотеки.

В `app/main.cpp`:

```cpp
#include <iostream>

#include "core/math_utils.hpp"

int main()
{
    std::cout << "2 + 3 = "
              << core::add(2, 3)
              << '\n';

    return 0;
}
```

## Простая ручная проверка

В `tests/test_math.cpp` нет тестового фреймворка и нет `assert`.

Это обычная программа:

```cpp
#include "core/math_utils.hpp"

int main()
{
    if (core::add(2, 2) != 4)
    {
        return 1;
    }

    return 0;
}
```

Если результат правильный, программа возвращает `0`. Для операционной системы это
значит: все хорошо.

Если результат неправильный, программа возвращает `1`. Это значит: проверка упала.

В `tests/CMakeLists.txt` эта программа регистрируется как тест:

```cmake
add_test(NAME math_utils COMMAND test_math)
```

CTest потом просто запускает `test_math` и смотрит на код возврата.

## Предупреждения компилятора

В `cmake/CompilerWarnings.cmake` лежит функция:

```cmake
function(enable_project_warnings target_name)
    if(MSVC)
        target_compile_options(${target_name} PRIVATE /W4)
    else()
        target_compile_options(${target_name} PRIVATE -Wall -Wextra -Wpedantic)
    endif()
endfunction()
```

Она включает предупреждения компилятора.

Для Visual Studio используется `/W4`.

Для GCC и Clang используются:

- `-Wall`;
- `-Wextra`;
- `-Wpedantic`.

Это помогает быстрее замечать странные места в коде.

## Внешние зависимости

В корневом `CMakeLists.txt` оставлены примеры:

```cmake
#find_package(Threads REQUIRED)
#find_package(Eigen3 3.3 REQUIRED NO_MODULE)
```

Они закомментированы, потому что сейчас проект не использует `Threads` и `Eigen`.

Позже, если эти зависимости понадобятся, можно будет раскомментировать строки и
добавить подключение библиотек к нужной цели.

## Как собрать проект

Сначала нужно создать папку сборки:

```bash
cmake -S . -B build
```

Что значит эта команда:

- `cmake` — запускаем CMake;
- `-S .` — исходники лежат здесь, в текущей папке;
- `-B build` — все файлы сборки положить в папку `build`.

После этого CMake прочитает `CMakeLists.txt` и подготовит проект.

Потом собираем:

```bash
cmake --build build
```

Что значит эта команда:

- `cmake --build` — собрать уже подготовленный проект;
- `build` — папка, где лежат файлы сборки.

## Как запустить приложение

```bash
./build/app/app
```

Ожидаемый вывод:

```text
2 + 3 = 5
```

## Как запустить тесты

```bash
ctest --test-dir build
```

Что происходит:

- CTest заходит в папку `build`;
- находит зарегистрированный тест `math_utils`;
- запускает программу `test_math`;
- если программа вернула `0`, тест считается пройденным;
- если программа вернула не `0`, тест считается упавшим.

## Зачем нужен `.gitignore`

Папка `build/` и временные файлы CMake не должны попадать в Git.

Их можно создать заново командой:

```bash
cmake -S . -B build
```

Поэтому в `.gitignore` добавлены файлы и папки сборки.

## Коротко вся логика

```text
1. В include/ пишем, какие функции есть.
2. В src/ пишем, как эти функции работают.
3. CMake собирает src/ в библиотеку core.
4. app подключает core и запускает код.
5. tests подключает core и вручную проверяет функцию.
6. ctest запускает проверку.
```

Такой шаблон можно использовать как стартовую точку для маленьких C++ проектов.
